# C의 기능 1차 MVP

작성일: 2026년 10월 26일 Asia/Seoul  
대상: C 기능 개발 담당자와 기능 검토자  
상태: 클레임 파일 변환과 사람 검토 후 송부 방식을 반영한 기능 검토안

C는 메일·엑셀·CSV로 접수한 클레임을 공통 정보로 변환하고, 관련 개별 보드의 생산라인과 보관 물량을 찾는다. 생산 중단 요청서와 출고·배송 중단 요청서를 작성해 사람이 검토하고 송부할 수 있게 한다. 이후 가상 불량 테스트와 조치 판정으로 재생산에 필요한 정상 제품 수량을 계산하고 A 전달용 요청서를 작성한다.

첫 MVP는 가정 자료를 사용한다. 시스템의 끝은 클레임 변환 결과와 요청서를 검토·저장·다운로드할 수 있는 단계다. 실제 송부는 사람이 기존 업무 채널에서 수행한다. 스키마 확장은 [온톨로지 담당자 전달안](C_온톨로지_스키마_확장_전달안.md)에서 다룬다.

## 1 현재 요구와 시연 가정

| 구분 | 내용 |
| --- | --- |
| 현재 요구 | 이미 납품한 제품의 클레임을 메일·엑셀·CSV로 접수한다. |
| 현재 요구 | 입력 형식을 변환해 고객·제품·일련번호·수량·현상 등의 공통 클레임 정보를 만든다. |
| 현재 요구 | 관련 생산라인과 보관 물량을 추적해 생산 중단 및 출고·배송 중단 요청서를 작성한다. |
| 현재 요구 | 사람이 요청서 내용을 검토·수정한 후 송부한다. 시스템은 자동 송부하지 않는다. |
| 현재 요구 | 가상 불량 테스트·조치 판정으로 재생산 필요 수량을 계산한다. |
| 현재 요구 | A 전달용 재생산 필요 요청서도 사람이 검토 후 전달한다. |
| 시연 가정 | 정해진 엑셀·CSV 양식과 일반 텍스트 메일 본문을 먼저 지원한다. |
| 시연 가정 | 기존 구성과 가상 보드·라인·재고·테스트 결과를 사용한다. 실제 제조사의 결함 사례가 아니다. |
| 후속 범위 | 임의 양식·이미지 OCR, 실제 메일 연동, 자동 송부, 현장 제어, 실제 재생산 실행을 정한다. |

테스트는 제품 불량의 재현·검사·조사를 위한 업무 단계다. 기본 목표는 무엇을 하는지 보여주는 것이며 가드레일 고도화·재시도·최적화는 중심 범위에 두지 않는다.

## 2 업무 흐름과 기능

```text
메일·엑셀·CSV 클레임 파일 입력
→ 형식별 추출과 공통 클레임 정보 변환
→ 사람의 추출값·대상 식별 확인
→ 생산라인과 관련 보관 물량 추적
→ 생산 중단 요청서 및 출고·배송 중단 요청서 생성
→ 사람 검토·수정 후 사람이 송부
→ 가상 불량 테스트와 조치 판정 확인
→ 재생산 정상 수량 산정과 A 전달용 요청서 생성
→ 사람 검토 후 사람이 A에 전달
```

| 기능 | 하는 일 | 사용자에게 보여줄 결과 |
| --- | --- | --- |
| 클레임 파일 접수·변환 | 형식별로 내용을 추출하고 필드·수량·시각을 공통 의미로 정리한다. | 원문과 변환 초안, 필드별 원본 위치, 누락·불일치 |
| 클레임 확인 | 고객의 일련번호·제품 설명을 기존 개체와 대조하고 사람이 확인한다. | 연결된 개별 보드·구성 또는 추가 확인할 후보 |
| 생산 이력 추적 | 확인한 보드에서 생산 기록과 현재 보관 정보를 조회한다. | 관련 라인과 보관 대상, 기준 시점·추적 근거 |
| 중단 요청서 작성 | 라인 가동 중단 요청과 보관 물량 출고·배송 중단 요청을 각각 문서로 만든다. | 대상·사유·범위·미확인·근거를 갖춘 검토 초안 |
| 사람 검토·송부 지원 | 사람이 내용을 수정·확인하고 저장·다운로드한다. | 검토할 문서와 검토 상태. 송부·수신·중단 결과는 사람이 확인한 기록이 있을 때만 표시 |
| 불량 테스트와 판정 | 선택한 가상 시나리오의 보드별 시험과 별도 조치 판정을 연결한다. | 관측 결과, 교체·대체·출고 허용·보류·미결 대상 |
| 재생산 산정·요청서 작성 | 확정 대체 수요에서 가용 대체 재고를 차감한다. | 추가 정상 수량, 근거·미확정과 A 전달용 검토 초안 |

생산라인을 찾지 못하면 추가 생산 이력이 필요하다고 표시한다. 제품 모델이 같다는 이유로 라인을 정하지 않는다. 초기 보관 물량 전체가 중단 요청 대상이어도 전체가 불량이거나 재생산 대상이라는 뜻은 아니다.

이미 운송 중이거나 고객이 보유한 다른 물량은 영향 후보로 표시할 수 있다. 현재 중단 요청의 기본 대상은 생산라인과 보관 물량이며 자동 회수·운송 중 회송은 별도 범위다.

## 3 요청서 생성과 사람의 검토 및 송부

요청서는 생산 중단 요청서와 출고·배송 중단 요청서로 나눈다. 첫 MVP는 편집 가능한 문서를 만들고 사람이 검토·저장·다운로드할 수 있게 한다. 기본 출력 예시는 Markdown이며 실제 서비스의 표시·저장 형식은 구현 시 정한다.

| 요청서 | 포함할 내용 |
| --- | --- |
| 생산 중단 요청서 | 사건·신고 현상, 관련 라인, 추적 근거, 요청 사유, 대상·범위, 미확인, 작성·검토 정보 |
| 출고·배송 중단 요청서 | 사건·생산 출처, 현재 보관 보드·재고 범위와 수량, 보류 요청 사유, 대상 목록·기준 시점, 검토 정보 |
| A 전달용 요청서 | 사건·구성, 필요한 정상 수량과 단위, 고객 교체·보관 대체·대체 재고의 산출 근거, 확정 여부 |

문서 생성, 사람 검토 완료, 사람이 송부한 사실, 수신자의 접수, 현장의 중단·보류 반영은 서로 다른 상태다. 생성 시에는 미검토·미송부이며 실제 중단 여부는 미확인이다. 검토만 끝났다고 송부나 현장 조치가 완료됐다고 표시하지 않는다. 사람이 송부·응답 기록을 남기는 입력은 둘 수 있지만 실제 메일 전송·제어 호출은 이번 MVP에서 수행하지 않는다.

수정한 문서의 버전과 검토 대상을 맞춘다. 이 과정은 복잡한 승인 체계를 새로 만드는 대신 기존 공통 초안·사람 검토 책임에 연결한다. 테스트 통과도 자동 라인 재개나 출고 허용을 뜻하지 않는다.

## 4 클레임 입력 형식과 변환 범위

### 지원할 형식

| 입력 | 첫 MVP에서 읽을 내용 | 범위 |
| --- | --- | --- |
| 메일 | `.eml`의 일반 텍스트 본문과 제목·발신·신고 정보 | 이미지·스캔·첨부 자동 해석, 실제 메일함 연동은 후속. 메일 본문을 복사한 텍스트 입력도 같은 내용 추출로 연결 가능 |
| 엑셀 | `.xlsx`의 고정된 `클레임` 시트, 첫 행의 정해진 열 이름, 이후 보드별 행 | 임의 시트·병합 셀·매크로·암호·복잡한 수식 양식은 첫 지원 범위에서 제외 |
| CSV | UTF-8 또는 UTF-8 BOM, 정해진 헤더, 보드별 한 행 | 구분자와 열 이름이 다른 양식은 매핑을 별도로 정한 후 확장 |

원본 보존 → 형식별 추출 → 공통 필드 매핑 → 시각·수량 정리 → 기존 제품·보드 조회 → 사람 확인 순서로 처리한다. 메일은 자연어 정보 추출, 엑셀·CSV는 정해진 열 매핑으로 시작한다.

### 공통 클레임 초안

| 항목 | 의미 |
| --- | --- |
| 고객 클레임 번호와 고객 | 고객이 붙인 원문 번호와 고객사. 내부 그래프 `id`와 구분 |
| 신고 시각 | 엑셀의 KST 시각·메일의 표현을 offset이 있는 시각으로 정리 |
| 제품 설명 | 제조사·제품 모델·설계 개정·변형을 원문으로 보존하고 기존 구성의 연결 후보를 조회 |
| 보드와 수량 | 고객 일련번호, 행별 수량, 합계. 확인된 경우 기존 `unit_id`에 연결 |
| 현상·발생 조건·고객 요청 | 신고 내용 그대로 정리. 고객 요청을 시스템 실행 명령으로 취급하지 않음 |
| 원본 위치와 미확인 | 파일과 해시, 메일 문단 또는 시트·셀·CSV 행, 누락·불일치·미연결 항목 |

고객이 생산라인·원인·보관 물량을 적지 않았다면 변환 단계에서 만들지 않는다. 실제 그래프에 없는 일련번호에는 `unit_id`를 부여한 척하지 않고 조회·등록 확인 대상으로 둔다. 신규 가정 보드를 시연 그래프에 등록하는 절차와 클레임 추출은 별개다.

엑셀·CSV는 불량 보드 한 대당 한 행, 행별 불량 수량 1로 준비한다. 같은 고객·클레임 번호의 반복된 고객·현상은 공통 정보로 묶고 수량은 보드별로 센다. 식별·수량이 맞지 않으면 사람 확인 항목으로 표시한다.

## 5 재생산 필요 수량의 계산

재생산 수량은 조사 범위나 배송 중단 물량 전체가 아니라, 정상 제품으로 채워야 한다고 판정된 수요를 기준으로 한다.

```text
확정 대체 필요 수량 = 고객 교체 필요 수량
                    + 보관 제품 중 대체 생산이 필요한 수량
추가 재생산 정상 수량 = max(0, 확정 대체 필요 수량 - 사용 가능한 대체 재고 수량)
```

계산은 구성별로 수행한다. 같은 보드가 여러 테스트에서 불합격해도 한 번만 센다. 보관 불합격 제품을 모두 자동으로 재생산하는 것이 아니라, 납품 수요를 충족하기 위해 대체가 필요하다는 판정·수요 근거를 함께 사용한다.

대체 재고는 같은 구성이며 이번 사건의 보류 범위 밖에 있고 다른 수요에 이미 배정되지 않은 물량으로 가정한다. 불량이나 보류 물량을 대체 재고에 포함하지 않는다. 미검사·판정 미결 물량은 미확정 수량으로 따로 표시하며 불량률로 전체에 확대하지 않는다.

A에 보내는 값은 필요한 정상 제품 수량이다. 부품 소요량, 생산 투입 수량, 구매나 실제 생산 실행 방식은 A의 범위가 정해진 후 연결한다.

## 6 가상 테스트의 공통 배경

다음 생산·고객·불량 자료는 모두 기능 설명을 위한 가정이다. 실제 OLIMEX의 결함·생산라인·검사 결과가 아니다. 공개 자료의 기존 `config:esp32-poe:L:WROOM` 구성을 재사용한다.

| 항목 | 공통 가정 |
| --- | --- |
| 클레임 | 이미 납품한 보드 5대에서 고객이 불량 현상을 신고하고 5대를 회수했다. |
| 생산라인 | `production-line:demo:C-01`. 이 라인에서 생산된 해당 구성의 완료 제품은 200대다. 현재도 별도 생산을 진행 중이다. |
| 200대의 위치 | 고객에게 납품된 80대와 보관 중인 120대로 나뉜다. 클레임 5대는 납품 80대 안에 포함된다. |
| 보관 물량 수요 | 보관 120대는 모두 유효한 납품 수요에 배정될 제품이며 폐기 판정된 수량만큼 대체 정상 제품이 필요하다. |
| 초기 중단 요청 | 관련 라인과 보관 120대를 대상으로 요청서를 작성한다. 사람이 검토·송부하며 실제 반영은 별도 확인한다. |
| 대체 재고 | 별도 라인에서 생산한 같은 구성 7대가 이번 사건 범위 밖에 있으며, 사용 가능·미배정으로 확인됐다고 가정한다. |
| 다른 납품 제품 | 클레임 외 이미 납품된 75대는 추가 영향 확인 후보로 표시한다. 교체가 결정되지 않은 상태에서 75대 모두를 재생산 수요에 넣지 않는다. |

보드는 새 가상 식별자를 쓴다. 고객 보드 C-D001부터 C-D080, 보관 보드 C-S001부터 C-S120, 대체 재고 C-R001부터 C-R007처럼 서로 다른 집합으로 관리한다. 기존 U104 등의 이력은 변경하지 않는다. 실제 그래프 ID는 공통 식별 규칙으로 발급한다.

각 시나리오는 위 배경에서 독립적으로 실행한다. 서로 다른 시나리오의 불합격 수량을 합산하지 않는다. 가상 테스트 결과는 준비된 기록을 입력하는 방식이며 실제 시험 장비를 조작하거나 물리 시험을 수행하는 기능은 요구하지 않는다.

## 7 있을 법한 불량 조사 시나리오

### 시나리오 1 전원 인가 후 부팅 실패

고객은 전원을 인가해도 일부 보드가 부팅하지 않는다고 신고했다. 회수 5대에서 부팅 실패가 재현되고, 보관 120대에 같은 기능 확인을 전수 수행했다고 가정한다. 접합부 관찰에서 이상 흔적이 있다는 기록을 원인 후보로 제공하되 이것만으로 원인을 확정하지 않는다.

보관 물량은 12대 불합격·108대 통과로 입력한다. 가정 조치 판정은 고객 5대 교체, 보관 불합격 12대 폐기 후 대체, 통과 108대는 담당자의 출고 허용으로 제공한다.

확정 대체 필요는 5 + 12 = 17대다. 대체 재고 7대를 사용하면 A에 전달할 추가 재생산 정상 수량은 **10대**다. 초기 보류 요청 대상 120대와 불합격 12대, 재생산 10대를 구분해서 보여준다. 라인 재개 여부는 별도 판단으로 남긴다.

### 시나리오 2 이더넷 연결이 간헐적으로 끊김

고객이 통신 중 연결이 끊긴다고 신고했다. 회수 5대에서 정해 둔 통신 확인 조건으로 증상이 재현되고, 보관 120대를 같은 조건으로 전수 확인해 18대 불합격·102대 통과로 입력한다.

장착 이력에서 특정 부품 로트와의 공통성이 보이면 조사 단서로 제시한다. 같은 로트라는 사실만으로 불량 원인이나 다른 제품의 불량을 확정하지 않는다. 대체 재고 7대는 해당 조사 범위 밖의 물량으로 확인된다는 공통 가정을 유지한다.

가정 판정은 고객 5대 교체와 보관 18대 대체다. 확정 대체 필요는 23대이고 대체 재고를 차감하면 추가 재생산 정상 수량은 **16대**다.

### 시나리오 3 신고 현상이 재현되지 않음

고객은 간헐적 부팅 실패를 신고했지만 준비된 조건으로 회수 5대를 확인했을 때 현상이 재현되지 않았다. 보관 120대도 이번 시험은 통과했다고 가정한다.

출고 허용 여부에 대한 담당자 판정이 없는 상태이므로 보류는 유지한다. 회수 5대는 발생 조건·사용 환경·추가 관측을 확인할 대상으로 남긴다. 이번 시험에서 재현되지 않았다는 사실을 클레임이 없었다거나 모든 제품이 정상이라는 결론으로 바꾸지 않는다.

고객 교체 판정이 미결이므로 최종 재생산 수량은 **미정**이다. 확정 대체 수요가 아직 없다는 값과 최종 재생산이 0으로 결정됐다는 의미를 구분한다. A에는 확정 수량 요청을 보내지 않고 추가 확인 상태를 표시한다.

### 시나리오 4 보관 제품의 표본 검사만 완료

회수 5대의 불량은 재현됐고 교체 필요가 판정됐다. 보관 120대 중 20대만 확인해 4대 불합격·16대 통과, 나머지 100대는 미검사라고 가정한다.

확인된 보관 불합격 4대의 대체 필요 판정까지 있으면 확정 대체 수요는 5 + 4 = 9대다. 대체 재고 7대를 반영한 추가 재생산 정상 수량의 하한은 **2대**이며, 미검사 100대의 조치에 따라 최종 수량은 달라진다.

표본의 불량률을 전체 120대에 곱해 최종 수량으로 쓰지 않는다. 최종 판정이 끝나지 않았으므로 첫 시연에서는 A 확정 요청을 보류하고 최소 2대·미확정 100대라는 검토 결과를 보여준다. 표본 통과 16대 역시 출고 허용 판정 전에는 보류 상태다.

## 8 A에 전달할 최소 정보

회의에서 정한 연결은 재생산 필요 정보를 A에 전달하는 지점까지다. A의 내부 기능·도구·최종 API는 확정하지 않는다. 첫 시연은 A 전달용 재생산 요청서를 작성하고 사람이 검토·송부한다.

| 항목 | 전달할 내용 |
| --- | --- |
| 사건과 대상 | 클레임 사건 식별자, 기존 `configuration_id`, 관련 개별 보드·라인과 근거 |
| 필요 수량 | 추가로 필요한 정상 제품 수량과 단위 |
| 산출 근거 | 고객 교체·보관 대체 필요 수량, 차감한 대체 재고, 중복 제외 기준 |
| 판정 상태 | 확정 가정 판정에 따른 요청인지, 하한만 계산했거나 추가 확인이 남았는지 |
| 필요한 시점 | 제시된 납품·교체 요구 시점이 있으면 그 근거와 함께 전달. 없는 날짜는 만들지 않는다. |

첫 시연은 시나리오 1·2의 확정 수량으로 요청서 초안을 작성해 사람 검토에 넘긴다. 사람이 검토 후 A에 송부한다. 시나리오 3·4는 추가 확인 상태로 두고 확정 요청서로 송부하지 않는다. 문서 생성·송부 기록을 실제 구매·재생산 완료로 설명하지 않는다.

## 9 역할과 검토 기준

클레임·조사 해석 역할은 사건과 추적 대상을 정리하고 테스트 결과를 설명한다. 조치·재생산 정리 역할은 판정 기록을 받아 수량을 계산하고 요청서 작성 도구를 사용한다. 파일 변환은 형식별 추출과 기존 식별자 연결을 담당한다. 하나의 C Agent로 먼저 시연할 수도 있으며 실제 Agent 수·이름은 확정하지 않는다. 집합 조회와 중복 제거·수량 계산은 공통 함수가 담당한다.

기존 Quality 역할의 장착 이력 조사 기능은 필요한 근거 조회에 재사용한다. 이 역할이 이미 클레임·불량 판정·라인 제어까지 지원한다는 뜻은 아니다. 사람의 조치 판정은 가정 입력으로 제공하거나 기존 사람 검토 경로와 연결하며 Agent가 승인 권한을 만드는 방식으로 구현하지 않는다.

| 확인할 장면 | 기대 결과 |
| --- | --- |
| 형식별 변환 | 메일·엑셀·CSV 예시를 각각 읽어 같은 클레임 번호·5개 일련번호·합계 5대·현상·시각을 얻고 원본 위치를 표시한다. |
| 변환 검토 | 미연결 일련번호·불명확한 구성·수량 불일치를 사람 확인 대상으로 남긴다. |
| 클레임 추적 | 고객 보드에서 라인과 생산 기록을 찾고, 해당 라인의 보관 120대를 구분한다. |
| 요청서 검토 | 두 종류의 중단 요청서를 생성하고 사람이 수정·검토한다. 미검토 초안은 미송부 상태이며 시스템이 전송하지 않는다. |
| 전수 테스트 | 시나리오별 검사 대상과 결과·조치 판정·재생산 수량이 연결된다. |
| 증상 미재현 | 추가 확인을 남기고 자동 정상 판정·보류 해제·재생산 0 확정을 하지 않는다. |
| 표본 테스트 | 미검사 100대를 표시하고 하한과 최종 미정을 구분한다. |
| 중복 검사 | 같은 보드의 여러 불합격 결과를 재생산 수요에 한 번만 반영한다. |
| A 인계 | 정상 수량 10대 또는 16대의 요청서와 근거를 만들고 사람이 검토 후 전달할 수 있다. |
| 생산 이력 부족 | 관련 라인을 만들지 않고 필요한 생산 기록을 표시한다. |

## 10 범위와 기준 자료

이번 결과물은 형식별 클레임 변환 초안, 추적 범위, 사람이 검토할 중단 요청서, 가상 테스트·조치 판정, 재생산 정상 수량과 A 전달용 요청서다. 가상 테스트로 실제 제품의 결함이나 실제 공장 조치의 효과를 검증한 것은 아니다.

실제 설비·물류 연동, 자동 회수, 라인 재개, 실제 폐기·수리·생산 실행, A 내부 처리와 B 연계는 후속 범위로 둔다. 임의 입력 양식 확장·자동 송부·메일함 연동은 후속이다. 지원하는 초기 양식과 사람 송부 원칙을 유지하면서 화면 구성·Agent 실행 방식은 구현 담당자가 선택할 수 있다.
