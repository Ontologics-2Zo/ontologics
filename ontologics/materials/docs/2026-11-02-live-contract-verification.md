# 실제 API 계약 해석 검증 — 2026-11-02

## 실행 범위

사용자 요청에 따라 실제 OpenAI API(gpt-5.4-mini-2026-03-17)를 호출했다. 고정 provider/해석 결과를 성공 근거로 사용하지 않았다. 로컬 계약 웹의 실제 등록·해석 경로와 기존 모델 비용 제한을 사용했다. 예시 구매자·번호·계약 내용만 전송했으며 실제 거래 계약은 사용하지 않았다.

기본 네 계약서는 기존 example_contracts 파일이다. 동일 의미 변형은 paraphrases 하위 네 파일이며, 상충/미합의 확인용 문서는 edge_cases 하위 두 파일이다. 원문은 수정하지 않고 해석을 새 버전으로 추가했다. 같은 파일의 중복 등록이 기존 고정 해석을 반환하는 것을 확인한 뒤, 기본 네 문서에도 명시적으로 실제 재해석을 실행했다.

## 발견한 문제와 수정

1. 실제 모델이 납기 변경 승인, 분할 납품 금지, 생산 전 사양 확인, 변경 합의서 관리 문구를 대체 정책에 포함했다. 추출 지침을 명확히 했으며, 명확한 전체 비정책 문구는 판단에서 제외하고 제외 사유와 원문을 보존한다. 알 수 없는 예외 문장은 임의로 제외하지 않는다.
2. 기존 문자열 규칙만으로 다른 표현을 분류하지 못했다. constraints claim에 한정해 policy_status 네 값을 허용한다. 원문 인용의 값·위치 검증 후 의미 해석을 사용하며, 알려진 전체 문장은 규칙을 우선한다. 서로 다른 상태가 함께 있으면 미확인으로 남긴다. policy_status에 approved 같은 실제 승인 상태는 허용하지 않는다.
3. 승인 전 기존 부품 유지 문장이 조건부 사용 허용으로 오해되었다. 승인 대기와 허용을 구분하는 지침 및 규칙을 추가했다.
4. 같은 납품 날짜와 그 날짜의 정확한 도착 시각이 충돌 처리됐다. 실제 원문에 있는 ISO 날짜/오프셋 시각이 동일 날짜를 가리킬 때만 명시된 시각을 선택한다. 시간을 새로 만들거나 다른 날짜/시각을 자동 선택하지 않는다. 기존 저장 해시를 바꾸지 않는 읽기 파생 결과를 UI와 확인 저장에도 동일하게 사용한다.

제품 코드는 materials 안에서만 수정했다. 회귀 테스트는 tests/materials에 추가했다. 공통 모델 provider, 권한, 비용 제한, 스키마는 변경하지 않았다.

## 실제 호출 결과

| 문서 유형 | 원본 결과 | 표현 변형 결과 |
| --- | --- | --- |
| 사전 승인 필요 | approval_required | approval_required |
| 대체 금지 | prohibited | prohibited |
| 승인 목록 내 허용 | conditional | conditional |
| 대체 조건 미기재 | unknown | unknown |

상충된 허용/금지 조항과 승인 조건 미합의 문서도 각각 unknown으로 유지했다. 최종 10건 모두 실제 모델 응답으로 검증했다. 수정 전 기본/변형 8건 중 6건은 잘못 미확인으로 표시됐고, 미기재 2건만 기대 결과와 일치했다.

최종 재검증 도중 대체 금지 문서 한 건에서 잘못된 근거 위치(EVIDENCE_OCCURRENCE_INVALID), 다음 재실행에서 JSON 형식 오류(INTERPRETATION_JSON)가 발생했다. 둘 다 기존 검증기가 차단했다. 근거/JSON 검증을 완화하지 않았으며, 그 다음 실제 호출은 성공했다. 따라서 모든 호출이 한 번에 성공했다는 의미는 아니다. 자동 재시도 로직을 새로 추가하지 않았다.

10건 모두 구매자명·사업자등록번호·제조사·제품명·개정·변형·수량·단위 및 납기 값을 확인했다. 같은 고객 ID로 연결되며, 제품 일치/생산 검토 준비 상태와 150대 자재 미리보기도 확인했다. 실제 BOM의 기존 미확인으로 자재 결과는 partial이며 이를 완전한 소요량 또는 생산 승인으로 취급하지 않았다.

## 검증 근거와 한계

API 호출은 초기 검증 8회, 첫 수정 후 8회, 최종 10회, 실패한 한 건 재실행 2회로 총 28회다. 운영 자료나 원시 모델 응답은 저장소에 추가하지 않는다. 로컬 임시 결과는 /private/tmp/live-policy-check/final-summary.json 및 flow-verification.json에 있다.

대체 조건 수정 후 전체 materials 493개 테스트가 통과했다. 이후 납기 보완을 포함한 materials 전체 회귀 495개가 258.690초에 통과했다. 마지막으로 한 인용 안의 상충 조항을 모델 상태로 덮어쓰지 못하도록 보강한 뒤 정책·납기·UI 대상 24개를 다시 실행해 모두 통과했다. 최종 서버에서 실제 해석 10건의 연결 흐름도 추가 모델 호출 없이 재검증했다. JavaScript 문법과 git diff 공백 검사 통과.

이 검증은 준비한 TXT 계약과 변형 사례 범위다. 임의의 모든 계약서 표현·PDF/OCR 정확성을 보장하지 않는다. 모델 의미 분류는 원문 근거와 함께 검토 가능한 해석이며, 특정 대체품의 실제 승인·적용 통제는 별도 업무다.
