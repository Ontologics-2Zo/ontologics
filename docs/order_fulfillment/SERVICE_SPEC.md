##### B-CQ01 — 계약의 납품 약속

가정 계약의 우리 회사/고객·기존 제품 구성·항목/회차 수량·단위·고객 도착 기한·납품 장소를 근거와 함께 등록하고 조회한다. `Contract → ContractItem → DeliveryRound`의 업무 관계를 기존 `Configuration`에 연결한다. 실제 참조 필드 방향은 DeliveryRound.contract_item_id → ContractItem.contract_id/configuration_id → Contract/Configuration이다. 공개 설계와 가정 계약의 근거는 별도이며 계약 수량은 보유·생산·납품 완료 수량이 아니다.

첫 입력은 고정 형식 Markdown 표의 계약 하나·항목 하나·회차 하나다. 추출 후보가 준비돼도 기존 초안·검증·사람 검토·서버 반영을 거친다. 누락·모호함·충돌은 보완 요청으로 남기며 제품 개정·기한 의미·시간대를 만들지 않는다. 고객 도착 기준만 지원하고 계약 유효기간·출고 기한·실제 인수를 혼동하지 않는다. 상세 규칙과 실행 예제는 [TOOLS의 B-CQ01](TOOLS.md#b-cq01-계약-접수와-약속-조회)을 따른다.

이 범위는 ‘누구에게 무엇을 언제까지 몇 대 납품하는 약속인가’까지다. 회차의 물량 현황·생산/도착 예상·납품 가능성·대응 초안은 후속 B CQ 확장이다. 실제 모델의 계약 해석·설명이나 범용 문서 OCR 지원을 완료했다고 보지 않는다. 기존 CQ01~10과 장착 이력 A/B의 번호·의미는 유지하며 B-CQ01은 별도 이름이다.

B 역할의 접수/약속 조회 실행 연결은 `examples/order_fulfillment/b_agent.py`로 제공한다. 접수는 원문 → 구성/근거 조회 → 미승인 초안/검증 → 사람 검토 대기, 조회는 사전 준비된 확정 회차 → 약속/근거/미확인 설명이다. 두 모드는 역할별 도구 권한을 공통 런타임에서 제한하고 모델 초안의 자동 승인 경로를 두지 않는다. 대역 연결과 실제 모델 품질의 검증 상태는 각각 기록한다.

## 추가·변경 3

> 원문 위치: 제조 제품정보 서비스 공통 기준 / 공통 의미와 데이터 경계 / B-CQ01 — 계약의 납품 약속 (100–135행)

##### B-CQ02 — 지정 시점의 물량 현황

승인된 같은 버전에서 납품 회차와 기존 구성을 연결하고 납품 완료·운송 중·창고·생산 중 미완성·준비 완료·대기의 배정 수량을 조회한다. 원천 재고/생산 작업의 상한은 다른 회차 배정을 포함해 먼저 검사하며, 실제 전량 출고한 과거 재고를 다시 창고에 더하지 않는다. 계약의 잔여 약속은 약속 수량에서 실제 납품 완료만 빼고, 미배정 수량은 약속에서 전체 배정을 뺀다.

`FulfillmentSnapshot`은 회사·회차 집합·정확한 현황 시점·근거 있는 확인 범위를 명시한다. 검색 결과 없음은 0이 아니며, 필요한 확인 범위가 부족하면 합계를 반환하지 않고 추가 확인을 요청한다. 완전성 표시는 원문을 검토한 사람의 주장으로 승인하며 코드가 문서의 의미 전체를 자동 입증하는 것은 아니다. 기존 장착 이력의 `HistoryCoverage`를 재사용하거나 의미를 바꾸지 않는다.

첫 형식은 비중복 집계 물량, 미완성 생산 작업, 배정 전량에 대응하는 단일 출고와 고객 실제 도착까지다. 부분 완료/출고·취소·반품·재배정·임의 시각 재구성은 이 현황 조회의 지원 밖이다. 생산 완료 예상은 별도B-CQ03 조회로 제공하며 도착 예측·납품 가능성 판단은 후속이다. 관측과 예정/실제 시각을 구분하고 예정 도착이 지났다는 이유로 도착 완료를 만들지 않는다. Task 08의 공통 도구를 Task 09의 읽기 전용 현황 역할에 연결했으며, 실제 모델 설명의 검증 결과는 PROJECT_STATUS를 따른다. 대역 성공만으로 실제 모델 성공을 선언하지 않는다. [실행 계약](TOOLS.md#b-cq02-물량-현황-조회)을 따른다.

##### B-CQ03 — 최근 생산 실적에 따른 조건부 완료 예상

같은 승인 버전의 `ProductionWork`·`Allocation`·회차와 새 `ProductionObservation`을 연결한다. 실적은 작업별 총생산·정상 완료·불량 **누계**이며 총생산=정상+불량,0 이상 정수·단위piece·UTC offset 포함 관측 시각을 검증한다. 전체 실적의 합계·누계 비감소·동일 UTC 순간 중복·시작 전/기준 시점 이후 모순을 검사한 뒤 최신 두 개의 증가량으로 계산한다. 회사·구성은 작업·회차·항목·계약 연결에서 확인하며 실적에 중복 정의하지 않는다.

첫 조회 범위는 한 작업의 정상 목표 전량이 한 회차의 약속 전량과 일치하는 경우다. 분할·복수 작업·다른 재고와 섞는 일정 조정은 미지원이다. 요청 `as_of`·snapshot·작업 상태·최신 실적은 같은 UTC 순간이어야 하며 `queried_at`은 별도 조회 실행 시각이다. 누락·오래된 현황·확인 범위 부족은 미확인과null로 남긴다. 기존 공통 저장에서 합법적인 분할·오래된 작업까지 전역 금지하지 않는다.

공통 Python이 최근 정상 속도와 잔여 정상 목표를 계산한다. 정상 수량에는 불량이 이미 제외돼 있으므로 불량률을 다시 차감하지 않는다. 중간 계산은 정확한 비율을 사용하고 최종 잔여 초만 올림한다. 정상 속도0이면 예상 시각을 만들지 않는다. 목표 확보를 관측하면 잔여 수량/시간0과 관측 시각만 반환하며 최초 실제 완료 시각·상태 전환·입고·납품 가능성을 생성하지 않는다. 최근 추세 계속·정상 완료분 사용 가능은 결과의 계산 조건이며 승인된 미래 사실이 아니다.
