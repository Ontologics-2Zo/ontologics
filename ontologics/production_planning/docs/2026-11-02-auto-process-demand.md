# 공정 자재 자동 필요량 연결

사용자가 확정한 흐름: 제품별 생산 수량 한 곳 → BOM 및 공정 자재 계산 → 부족량 → RFQ 초안. production_planning 내부만 수정한다.

- 서버 Decimal 산식: 대당 기준 × 생산 수량 × (1 + 여유율/100), 6자리 올림. 기준 없는 자재는 null/미등록.
- 원문 조건부 기준/초기 충전량 미포함을 문서에 유지. 매 작업 수동 총량 입력 제거.
- 조회는 저장하지 않는다. RFQ 저장 시 최신 재고·근거 해시 확인 후 자동 검토 스냅샷과 초안 저장. 기존 수동 검토/문서는 읽기 호환.
- 제품 수량 변경 시 BOM과 공정 조회 함께 갱신. 요청 순번으로 오래된 응답 무시, 변경 중 이전 RFQ 차단.
- 테스트: 100/200대, 10/20% 여유율, 미등록 3종 제외, 재고 변경 차단, 저장/재조회/문서 수량 일치.

## 구현 및 검증

- `process-requirement-preview`: 생산 수량/여유율만 받아 서버에서 계산한다. 조회 시 검토 레코드를 만들지 않는다.
- `process-requirement-auto`: 계산 기준 해시 일치 여부를 확인하고 서버 계산으로 검토를 저장한다. 클라이언트 총필요량 입력을 받지 않는다.
- 기존 `process-rfq-create`는 자동 검토의 대당 기준을 재계산하고 부족 자재만 저장한다. 기존 수동 검토/초안은 읽기 호환을 유지한다.
- UI: 제품 수량 입력 후 350ms에 BOM과 공정 자재를 함께 갱신한다. 입력 즉시 이전 RFQ 저장을 막고 요청 순번으로 오래된 응답을 무시한다. 여유율·요청 조건은 수량 변경 시 유지한다. 총필요량·추가 생산 수량 입력란은 없다.
- 관련 16개 테스트 통과 (`/private/tmp/auto-demand-tests.log`). Node 문법 검사와 git diff --check 통과.
- 실제 UI: 100→200대 변경 시 BOM 100k 저항 필요량 200개/부족185개, 페이스트 필요45.9954g, 플럭스 필요58.828g/부족45.828g 확인. 200대·여유20%는 플럭스 부족51.176g. 0대는 RFQ 저장 불가. 새로고침 후 저장된 200대 문서와 현재100대 계산을 구분해 표시.
- 사용자 로컬 DB에 검증용 미발송 RFQ 1개 저장: 검토ID `7119f687-114f-4e8f-a418-e25016f5025d`, 작업명 `자동 연결 검증 · 200대`, 부족45.828g. 실발주·발송·재고 예약/차감 없음.
