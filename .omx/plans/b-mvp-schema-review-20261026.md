# B MVP 스키마 전달안 반영 계획 — 직접 계획 작성

작성일: 2026-10-26. 사용자 요청은 전달안 보존·작업계획 재점검/수정·Task 01 설명 자료 작성이다. 구현 요청으로 확대하지 않는다.

## 요구와 결정

- 전달안은 JunhwaDocs에 원문 그대로 보존한다. 현재 스키마의 확정 계약과 구분한다.
- Task 01~06 본문·체크 상태와 기존 결과는 유지한다. 새 자료는 미완료 Task 06의 검토 자료다.
- 기존 B-CQ01~06을 유지하고 Task 07~10에 CQ별 최소 스키마·검증·자료·공통 도구·Agent·검증 작업을 구체화한다.
- Task 01은 기존 결과를 근거로 별도 설명 자료를 만든다. 원격 fetch를 새로 했다고 쓰지 않는다.

## 정식 작업계획과 근거

사용자가 읽을 정식 계획은 [JunhwaDocs/B_MVP_작업계획.md](../../JunhwaDocs/B_MVP_작업계획.md)다. 5장의 실행 단계·완료 기준, 6장의 CQ별 의존성, 15장의 코드 근거·위험·미결정 항목을 따른다. 이 파일은 별도의 실행 계획을 만들지 않는다.

## 검증 기준

1. 복사본의 SHA-256이 Downloads 원본과 일치한다.
2. 기존 Task 01~06 구간과 수치 시연 구간, 다른 기존 참고 문서 내용은 작업 전 백업과 일치한다.
3. 새 설명 자료의 링크·계획 링크·과거 결과/미검증 상태와 변경 문서 공백 검사를 확인한다.
4. 현재 코드·HEAD·브랜치를 유지하고 PROJECT_STATUS는 이번 문서 검토 기록만 덧붙인다. 코드 테스트·DB·모델 실행은 하지 않는다.

## 위험과 처리

후보 타입을 이미 구현된 계약처럼 읽을 위험은 명시적인 제안 상태와 미래 체크 항목으로 줄인다. 공통 자료 정책·숫자/시간/선택 참조·JSON-LD의 누락은 Task 08과 코드 대조표에 반영한다. 중복 물량은 상태별 정답·배정 규칙으로 검증하며 일반 상태 전환 지원 범위는 Task 06/B-CQ02에서 결정한다. API 키 누락에 따른 Task 05 실모델 미검증은 그대로 남긴다.
