# C 클레임 대응 시나리오 입력 파일

`python -m examples.claim_response.scenario_app`으로 화면을 띄운 뒤(http://127.0.0.1:8765), 아래 파일을 순서대로 올리며 진행한다. 모두 가상 자료다. 고객사·납품 문서(가정 고객사 C-01, DO-DEMO-C-001)와 신고 시각(2026-10-26 10:00 KST)은 가정 운영 기록(`data/claim_response/operations.json`)에 맞춰 같게 두었다. 보관 재고가 그 시각에 관측됐기 때문이다.

| # | 상황 | 1) 클레임 파일 | 2) 테스트팀 결과 파일 | 기대 결과 |
|---|---|---|---|---|
| 1 | 메일 접수. "PoE 연결 후 이더넷 링크 LED 미점등" 3대(C-D021~023). 전수 시험에서 보관품 10대 불합격 | `1_메일_전수시험_클레임.eml` | `1_테스트팀_결과.csv` | 의뢰 123대 → 고객 교체 3 + 보관 대체 10 − 대체 재고 7 = **재생산 확정 6대** |
| 2 | 엑셀 접수. "장시간 가동 후 재부팅 반복" 4대(C-D040~043). 보관품 30대만 표본 시험, 6대 불합격 | `2_엑셀_표본시험_클레임.xlsx` | `2_테스트팀_결과.csv` | 시험 34 / 미검사 90 → 4 + 6 − 7 = **하한 3대** (최소 수량) |
| 3 | CSV 접수. "간헐적 네트워크 끊김" 2대(C-D060~061). 72시간 시험에도 증상 미재현 | `3_CSV_증상미재현_클레임.csv` | `3_테스트팀_결과.csv` | 미결 2, 보관 120 보류 → **재생산 미정**, A 요청서 없음 |
| 4 | 메일 접수. 고객이 C-D073을 C-D730으로 잘못 적음 | `4_메일_일련번호오기재_클레임.eml` | (없음) | 2대만 연결, C-D730 못 찾음 → **추적 단계에서 멈춤**, 사람 확인 |
| 5 | CSV 접수. "USB 인식 안 됨" 2대(C-D015~016). 테스트팀 첫 결과 파일에 오류 | `5_CSV_결과파일오류_클레임.csv` | 먼저 `5_테스트팀_결과_오류.csv`, 그다음 `5_테스트팀_결과_수정본.csv` | 첫 파일: C-S041 중복(재시험 행), 의뢰하지 않은 C-D017, C-S100 시간대 누락 → **차단, 저장 0건**. 수정본: 2 + 8 − 7 = **재생산 확정 3대** |

클레임 추적(3단계)은 실제 모델(`gpt-5.4-mini-2026-03-17`)도 한 번 수행하며, 모델 답이 함수 계산과 같을 때만 인정한다. `.env.local`의 키와 비용 상한·단가가 필요하고 클레임 하나에 1센트 안팎이 든다. 비용 없이 보려면 `--scripted`로 실행한다(대역).

진행 순서(화면이 다음 할 일을 하나씩 보여 준다): 클레임 파일 올리기 → 변환 내용 확인 후 등록 → 고객 클레임으로 확인(추적 자동) → 중단 요청서 검토 승인 → 테스트팀에 송부했음으로 기록 → 테스트팀 결과 파일 올리기 → A 요청서 검토 승인. 요청서는 화면에서 펼쳐 보거나 내려받을 수 있다(`artifacts/local/claim_response/app/`). 올린 파일은 `data/claim_response/uploads/`에 보관되며 Git에 올라가지 않는다.
