# 계약 구매자 자동 연결

## 범위와 흐름

제품 코드는 materials 안에서만 변경한다. 공통 서비스·권한·그래프 스키마는 변경하지 않는다. 회귀 테스트는 tests/materials에 둔다.

등록 화면은 파일과 제목만 받는다. 계약 해석에서 구매자를 추출하고 원문 근거를 검증한 뒤 로컬 고객 DB에 연결한다. 과거 등록 화면의 거래처 입력값은 구매자 근거로 사용하지 않는다.

- 사업자등록번호와 회사명이 일치하면 기존 고객에 연결한다.
- 번호가 없으면 정규화한 회사명이 유일하게 일치할 때 연결한다. 후보가 없으면 회사명 기준 고객을 자동 생성한다.
- 동일 이름의 고객이 여러 곳이면 후보 선택을 요청한다. 구매자 누락·근거 충돌·사람의 보류가 있으면 구매자 확인을 요청한다.
- 회사명 연결은 법인 실체 검증이 아니다. 미등록 번호는 별도 고객으로 만들며, 이름만 같은 고객에 강제로 합치지 않는다.
- 수량 등 무관한 정보 수정은 기존 고객 선택을 유지한다. 구매자 근거 변경은 연결을 재평가한다.

## 엔티티와 관계의 역할

Customer 엔티티(pp_customers)와 ContractBuyer 관계(pp_contract_buyers)를 도메인 PostgreSQL 테이블로 구현했다. 공통 RDF/그래프에 새 클래스를 추가한 구현은 아니다.

계약마다 구매자 문자열만 저장하는 대신 고객 ID를 공유하므로 동일 고객의 여러 계약을 조회할 수 있다. 관계는 원문 해시, 해석 버전, 확인 기록, 구매자 근거 지문과 연결 방법을 보존한다. 원문이나 구매자 해석이 바뀌면 오래된 관계를 현재 사실로 사용하지 않는다. 고객 → 계약 → 기존 제품 구성·BOM 검토 흐름이 이어지며, 고객 확인을 계약마다 반복하지 않는다. 생산·구매 승인은 자동 고객 연결과 별개다.

## 구현 파일

- customer_library.py: 고객 저장·검색·자동 연결·후보 선택·현재 계약 이력.
- contract_intake.py / contract_interpretation.py: 선택적 구매자 사업자등록번호 및 구매자 역할 해석.
- contract_library.py / contract_library_web.py: 검색 연계, 고객 API, 등록·해석·확인 후 동기화.
- library_static/index.html / app.js: 거래처 입력 제거, 구매자 자동 표시, 예외 질문과 고객 계약 이력.
- auto_review_demo.py: 결정적 고객 연결 시나리오 준비.
- tests/materials/test_customer_library.py / test_auto_review_ui.py: DB·근거·권한·후보·화면 실패 복구 검증.

## 웹 테스트

http://127.0.0.1:51171 에서 다음 계약을 연다.

| 번호 | 확인할 동작 |
| --- | --- |
| 05 / 06 | 구매자 자동 연결, 같은 고객의 계약 2건 |
| 07 / 08 | 동일 이름·서로 다른 번호를 별도 고객으로 저장 |
| 09 | 번호 없는 동명 구매자의 후보 선택 |
| 10 | 구매자 누락 시 확인 질문 |

```sh
python3 -m ontologics.materials.auto_review_demo --local-test-fixtures --customer-scenarios --schema a_contract_library
```

준비 자료는 가상 원문과 결정적 해석 대역을 사용한다. 이번 테스트에서는 유료 모델 호출을 하지 않았다. 실제 파일의 모델 해석 정확도는 별도 검증 대상이다. 기존 계약은 원문을 변경하지 않고 저장된 해석 근거로 고객 연결을 보완했다.

## 검증 결과

생산 계획 테스트 477개 실행에서 테스트 DB 환경변수 불일치로 오류 4건(하위 시나리오 포함)이 발생했다. 환경을 바로잡은 뒤 해당 실패 항목을 포함한 14개 재검증이 모두 통과했다. 새 고객 테스트 8개와 UI 테스트를 포함한다. JavaScript 문법 및 git diff 공백 검사 통과.

실제 브라우저에서 거래처 입력 제거, 자동 연결 및 계약 2건 조회, 동명 후보 표시, 구매자 누락 질문을 확인했다. 고객 이력 조회 오류가 생산 검토 화면을 중단하지 않는 것도 UI 회귀 테스트로 확인했다.
