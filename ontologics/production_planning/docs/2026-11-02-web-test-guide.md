# 계약 자동 검토 웹 테스트

현재 테스트 주소: http://127.0.0.1:51171

목록에서 **[자동 검토 테스트] 04 직접 테스트 · 확인 기록 없는 정상 계약**을 열고 **생산 검토 시작 →**을 누릅니다. 사람 확인 전에도 제품 일치와 주문 100대 기준 총소요량이 나옵니다. 실제 BOM의 미확인 항목은 미확인으로 남습니다.

1. **정상:** 내용 확인·제품 연결 후 생산 수량 검토 → 버튼 하나로 다음 단계로 이동합니다. 실제 생산 검토 수량과 근거는 따로 입력합니다. 주문량을 자동으로 생산량으로 채우지 않습니다.
2. **누락:** 02 개정 누락 계약은 설계 개정만 필요한 질문으로 보여줍니다. 납기·이행·배정량 누락 때문에 질문을 늘리지 않습니다. 필요한 계약 정보 수정 → 설계 개정을 직접 수정하고 사유를 입력 → 해석 내용 확인 완료 → 같은 자동 검토 화면에서 결과를 확인합니다.
3. **충돌:** 03 수량 충돌 계약은 100/120 중 하나를 자동 선택하지 않습니다. 원문 근거를 확인하고 수량과 수정 사유를 직접 저장해야 자동 계산을 볼 수 있습니다.
4. **재방문:** 01 정상 계약은 구현 검증 중 확인·제품 연결과 70대 기준 자재 검토 저장을 완료했습니다. 저장된 연결로 다시 진행할 수 있고 부족 부품 검토·구매 요청 화면까지 연결됩니다. 구매 요청 발송·발주는 하지 않았습니다.

계약 수정 중에는 이전 미리보기를 최신 결과로 표시하지 않고 다음 진행 버튼을 잠급니다. 내용을 저장하면 새 결과로 다시 계산합니다. 연결 중 실패하면 확인 기록과 제품 연결 상태를 다시 읽고 남은 단계를 재시도합니다.

이 자료는 **가상 원문 + 결정적 해석 대역**입니다. 실제 모델 해석 정확도 검증이 아닙니다. 기존 계약은 수정·삭제하지 않았습니다. 새 파일 업로드나 다시 해석하기는 기존 실제 모델 연결을 사용하므로 모델 호출이 발생할 수 있습니다.

## 다시 준비하기

기존 환경의 PostgreSQL 및 모델 설정이 준비된 상태에서 저장소 루트에서 실행합니다.

```sh
python3 -m ontologics.production_planning.auto_review_demo --local-test-fixtures --schema a_contract_library
python3 -m ontologics.production_planning.contract_library_web --port 51171 --schema a_contract_library
```

시나리오 준비는 로컬 DB만 허용하고 같은 자료를 중복 생성하지 않습니다. 이미 사람이 확인한 테스트 계약을 초기화하거나 확인 기록을 삭제하지 않습니다. 웹에 계약만 있고 제품 목록이 없다면 기존 승인·개발 준비 경로로 제품 카탈로그를 먼저 준비해야 합니다. 이번 준비 도구는 공통 그래프를 임의로 등록하지 않습니다.

## 검증 범위

원문 근거 검증과 자동 계산은 사람 확인·생산 승인과 다릅니다. 구매·예약에는 기존 명시적 저장 경로를 사용합니다. 공통 모델·승인·권한·스키마는 변경하지 않았습니다.
