# 구매팀 RFQ 메일 작성·전달·보관

사용자 요청: Microsoft 계정 연결과 수동 발송 증빙 입력을 없애고, 구매팀 선택 → 자동 작성된 메일 수정 → RFQ 자동 첨부 확인 → 보내기 → 기록 재조회로 단순화한다. `materials`와 생산·자재 계획 화면, 관련 테스트만 변경한다. 공통 코드·스키마·다른 업무 화면은 수정하지 않는다.

## 동작

1. 저장된 검토 결과의 RFQ를 서버에서 다시 읽고 무결성을 검사한다. 제목·본문은 계약 또는 추가 요청과 계산 결과에서 준비한다. [RFQ 수정·저장](2026-11-04-rfq-edit-plan.md)에서 수정본을 선택했다면 그 문서 ID·버전·원본 근거를 확인하고 첨부하며, 메일에도 담당자 수정 문서임을 명시한다.
2. 구매팀 연락처를 선택하고 제목·본문을 수정한다. 더미 연락처는 가상임을 표시하며 `.test` 주소를 실제 외부 SMTP에 전송하지 않는다.
3. ‘첨부·내용 검토’에서 수정한 내용과 정확한 RFQ 바이트를 초안으로 보존한다. 서버가 작성 시각·Message-ID와 MIME 원문을 고정하며 이 단계는 발송하지 않는다.
4. 사용자가 보내기를 누르면 보존한 MIME 원문으로 전송하고, 서버의 전송 시도 시각·접수 시각을 작성 시각과 별도로 기록한다. 동일 초안은 한 번만 전송 시도한다. 결과 불명확·서버 중단 시 자동 재전송하지 않는다.
5. 전송 결과와 그래프 등록 결과를 분리한다. 메일 보관이 성공해도 그래프 등록이 실패할 수 있으며, 그래프만 재시도한다.
6. 기록에서 수신자·제목·본문·시각·상태를 다시 읽고 보존된 RFQ와 EML을 내려받는다. 기존 수동 전달 증빙도 별도로 조회할 수 있다.

## 전달 방식과 상태

- 기본값은 서비스의 **시험 메일함**이다. 계정 등록 없이 더미 구매팀으로 전달하고 이력을 확인한다. 작성·미리보기의 반복 안내 문구는 생략하고 ‘시험 메일함으로 보내기’ 버튼과 ‘시험 메일함에 보관됨’ 결과 상태로 구분한다.
- 실제 외부 전달은 관리자가 회사 SMTP와 실제 연락처를 설정한다. 사용자별 Microsoft 로그인은 없다. TLS와 신뢰된 서버 설정을 사용하며 화면이 임의 SMTP 서버·발신자를 지정할 수 없다.
- SMTP 성공은 ‘메일 서버 접수됨 · 수신 확인 안 됨’이다. 수신자 열람·최종 배달을 확인한 것으로 표시하지 않는다.
- 실패와 결과 불명확을 보존한다. 불명확한 결과는 새 메일로 자동 재시도하지 않는다.

## 변경 파일

- `materials/rfq_mail.py`와 전송 어댑터: 연락처, 초안, 한 번의 전송 시도, 보관 및 재조회.
- `materials/rfq_handoff.py`, `materials/rfq_handoff_document.py`: 자동 전송 기록의 출처를 기존 수동 증빙과 구분하고 기존 공통 SourceDocument/Evidence 등록안을 재사용.
- `materials/workspace.py`: 기존 A POST 경로에 메일 작업 연결.
- `static/planning.js`: A 메일 작성·미리보기·기록 화면. 날짜·증빙 업로드·Microsoft 연결 입력 제거.
- `tests/materials/`: 정확한 첨부·권한·중복 전송·실패·재시작·그래프 재시도 검증.

새 RFQ/메일 노드 타입이나 스키마를 추가하지 않는다. RFQ의 계약·제품·계산 근거 참조와 메일 원문을 SourceDocument/Evidence로 남기며 그래프 반영은 기존 별도 검토·승인을 따른다. 실제 SMTP 접수 기록과 가상 RFQ의 출처도 각각 유지한다.

## 검증 계획

- 실제 격리 PostgreSQL에서 초안 저장은 전송하지 않음, 수정 내용·정확한 RFQ 첨부, 소유자·읽기 권한, 동시·중복 요청, 실패·결과 불명확, 재시작 후 보관 조회 검증.
- 로컬 시험 메일함과 SMTP 경계 대역으로 전송 결과를 구분. 실제 외부 수신자에게 테스트 메일을 보내지 않는다.
- Chrome에서 180대 계약 → 자재 검토 → RFQ → 구매팀 선택·메일 수정 → 미리보기 → 시험 전달 → 새로고침 후 재조회 → 별도 승인·그래프 반영 검증.
- 관련 테스트, 최종 전체 회귀 및 A 영역 변경 범위를 확인하고 결과를 아래에 기록한다.

공식 구현 근거: [Python EmailMessage](https://docs.python.org/3/library/email.message.html), [Python SMTP](https://docs.python.org/3/library/smtplib.html).

## 운영 설정

기본값은 `MATERIALS_MAIL_TRANSPORT=local_capture`이며 추가 계정 없이 사용할 수 있다. 구매팀 견적 접수·전자부품 담당·공정자재 담당의 세 더미 연락처를 제공한다. 개발 메일과 증빙은 `data/receipts/materials/` 아래 저장소별로 분리해 보관하며 저장소에 커밋하지 않는다. 운영 배포 시 이 디렉터리는 지속 볼륨·백업 대상이다.

실제 외부 이메일은 관리자가 아래 환경 설정을 한 번 준비한다. 각 사용자가 Microsoft 앱을 등록하거나 로그인할 필요는 없다. 비밀번호를 브라우저·문서·커밋에 넣지 않는다.

| 변수 | 내용 |
| --- | --- |
| `MATERIALS_MAIL_TRANSPORT` | 외부 발송은 `smtp` |
| `MATERIALS_MAIL_FROM`, `MATERIALS_MAIL_FROM_NAME` | 회사가 허용한 발신 주소와 표시 이름 |
| `MATERIALS_MAIL_CONTACTS` | `{id,name,email,origin}` 객체의 JSON 배열. 실제 연락처는 `origin: real`, 더미는 `synthetic` |
| `MATERIALS_SMTP_HOST`, `MATERIALS_SMTP_PORT` | 회사 SMTP 호스트·포트 |
| `MATERIALS_SMTP_TLS` | `starttls`(기본 587) 또는 `ssl`(기본 465). 평문 연결 없음 |
| `MATERIALS_SMTP_USERNAME`, `MATERIALS_SMTP_PASSWORD` | 서버가 요구하는 인증 값. 인증이 필요하면 두 값을 함께 제공 |

`.test` 주소는 SMTP 설정 여부와 무관하게 시험 메일함에만 저장한다. 발신자·수신자·전송 대상이 초안 저장 후 바뀌면 기존 초안을 다른 대상으로 보내지 않고 새로 검토하도록 차단한다. SMTP 접속 설정과 자격 증명은 메일 이력 응답에 노출하지 않는다.

## 검증 결과 (2026-11-04)

- 메일·SMTP 경계·기존 수동 증빙·A HTTP 관련 **43개 테스트 통과**. 실제 격리 PostgreSQL에서 저장·읽기 권한, 공유된 전송 기록, 동시 요청의 단일 전송 시도, 재시작, 파일 일부 저장 실패 복구, SMTP 접수 후 결과 파일 저장 실패, 그래프 등록 실패와 재시도, 변경된 관리자 설정 차단을 확인했다.
- 실제 Chrome에서 180대 계약 → 계산 → RFQ → 구매팀 선택 → 제목·본문 수정 → 미리보기 → 시험 전달 → 새로고침 후 기록 재열기를 확인했다. MIME에 첨부된 RFQ 7,627바이트가 저장된 RFQ와 정확히 같았다. 원문 해석만 모델 대역을 사용했다.
- 같은 전송 재호출은 기존 기록을 반환한다. 별도 새 작성은 새 초안을 만들고, 저장이 끝난 뒤 응답만 유실된 재시도는 같은 키·초안으로 복구하는 것을 브라우저에서 확인했다.
- 자신의 증빙 승인 차단, 다른 사용자 검토·승인, 그래프 v2 반영과 정확한 증빙 재조회를 확인했다. 모바일 390px 가로 넘침 및 JavaScript 오류가 없었다.
- SMTP는 실제 `smtplib` 실행을 포함한 프로토콜 경계 대역으로 검증했다. 외부 메일 발송은 0회다. 회사 SMTP 계정으로 실제 발송·배달은 검증하지 않았으며 기본 화면은 시험 메일함임을 표시한다.
- 시험 서버·스키마·임시 보관 기록은 정리했다. 브라우저 증거는 `/private/tmp/simple-mail-e2e/`에만 보관한다. 사용 중인 8062 서버는 기존 DB/schema/graph 설정으로 재시작했으며 실제 RFQ의 메일 준비·더미 연락처 3건·기록 조회와 데이터 버전 유지를 읽기 전용으로 확인했다.
- 독립 코드 검토에서 발신자 표시, 작성 화면 복귀, 부분 저장 복구, 새 작성과 재시도 키 분리 문제를 수정한 뒤 재검증했다. 공통 코드·스키마·다른 업무 화면을 변경하지 않았다.
- 최종 전체 unittest discovery: **1,755개 실행, 실패·오류 0, 환경 조건 skip 11**, 749.668초. 새 메일 관련 43개는 모두 실행됐다. 기존 Shapely 2 및 명시적인 통합 환경 조건에 따른 건너뜀을 성공으로 계산하지 않는다. 전체 로그: `/private/tmp/simple-mail-full-tests.log`. JS 구문·diff 공백·A 전용 파일 범위도 최종 확인했다.
