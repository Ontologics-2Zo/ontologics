# claim_response 데이터 정책 추가

> 기능: C 클레임 대응 (`claim_response`)
> 기준 문서: [서비스 명세 - 공통 의미와 데이터 경계](../SERVICE_SPEC.md), [C 온톨로지 스키마 확장 전달안](references/C_온톨로지_스키마_확장_전달안.md) 10장 "자료 정책과 구현 반영 요청"
> 상태: 팀 승인 완료. 이 문서는 **PR #6(1차) 범위**만 허용한다. 시험·재생산 기록은 PR #7에서 별도로 추가한다.

## 1. 요약

- 기존 허용 범위는 그대로 둔다. C 클레임 대응에 필요한 가상 기록만 **추가로** 허용한다.
- PR #6에서 허용: 생산라인과 보드별 생산 기록, 고객 클레임, 그리고 이를 잇는 품질 사건·영향 범위·중단 요청서 (타입 6개).
- 시험 결과·조치 판정·재생산 요건은 **이 PR에서 허용하지 않는다.** PR #7에서 범위와 조건을 따로 정한다.
- 모두 시연용 가상 기록이며 실제 OLIMEX 제품의 결함이나 실제 공장 조치로 설명하지 않는다.

## 2. 기존 정책 원문

`SERVICE_SPEC.md` "공통 의미와 데이터 경계":

> 실제 자료는 OLIMEX 공개 사양·설계·BOM이다. 가상 기록은 회사의 재고·입출고, 개별 제품·부품 로트 식별, 장착·제거와 그 이력의 확인 범위에 한정한다. 가상 검사 결과·고장 원인·불량률·가동 시간은 허용 범위에 추가하지 않는다. 사용자 조사 요청과 확인된 사실도 구분한다.

C 기능은 이 범위 밖의 기록(클레임, 생산라인과 생산 기록, 이후 시험 결과·조치 판정)이 필요해서 전달안 10장으로 정책 보완을 요청했고 팀 승인을 받았다. 근거 자료는 [references](references/README.md)에 원문으로 보관한다.

## 4. 지켜야 할 조건 (PR #6)

1. 위 1차 타입은 모두 `origin=synthetic`이다. 공통 모델의 `SYNTHETIC`에 포함되어 있어 `real`로 넣으면 `DEMO_OPERATIONS_ONLY`로 거부된다.
2. 모든 노드는 가상 `SourceDocument`·`Evidence` 근거를 가진다. 원본 파일은 `data/claim_response/` 안에 둔다.
3. 고객사·클레임 번호·납품 문서 번호는 가정 값이며 `DEMO` 표시를 넣는다(예: `DO-DEMO-C-001`). 실제 회사·고객 이름을 쓰지 않는다.
4. `reported_symptom`은 **고객 신고 원문**이다. 확인된 고장이나 고장 원인으로 표현하지 않는다.
5. `QualityScope`의 보드 목록은 **조사·보류 대상**이다. 불량 보드 목록이 아니다.
6. 중단 요청서의 생산라인은 그 요청서가 가리키는 영향 범위의 생산라인과 같아야 한다(`LINE_MISMATCH`). 다른 라인에 대한 요청이 필요하면 자동으로 허용하지 않고, 별도 의미·근거 계약을 먼저 정한다.
7. `UnitProductionRecord.production_work_id`는 **미지원 접점**이다. 공통 `ProductionWork` 타입은 있지만 C 보드가 어느 생산 작업에 속하는지 B와 합의하지 않았으므로(B·C 통합 결정 I02) 값을 넣으면 `PRODUCTION_WORK_UNSUPPORTED`로 거부한다.
8. 같은 라인이나 같은 부품 로트라는 공통점으로 고장 원인을 자동 확정하지 않는다.
9. 실제 OLIMEX 자료(사양·설계·BOM)에 C 기록을 섞지 않는다. 연결은 이미 가상인 `ProductUnit`을 통해서만 한다.

## 5. 여전히 허용하지 않는 것

- 고장 원인 확정, 불량률, 가동 시간
- 시험 결과·조치 판정·재생산 요건 (PR #7 범위, 이 PR에서는 타입이 없어 `UNKNOWN_TYPE`)
- C 범위 밖의 가상 검사 기록(장착 이력 조사 등 기존 기능에 시험 결과를 끼워 넣는 것)
- 기존 자유 필드에 시험·원인 정보를 넣는 방식
- 완성 보드 재고·출하(`FinishedGoodsStock`, `Shipment`)는 B 정의를 따른다. C에서 따로 만들지 않는다.

## 6. 공통 문서 반영

`SERVICE_SPEC.md` "공통 의미와 데이터 경계"의 기존 문장 뒤에 아래 문장을 추가했다. 기존 문장은 지우지 않았다.

> C 클레임 대응 범위에 한해 생산라인과 보드별 생산 기록, 고객 클레임, 품질 사건·영향 범위, 생산 중단·출고 보류 요청서를 가상 기록으로 허용한다. 클레임 증상은 고객 신고 원문이며 확인된 불량이나 원인이 아니다. 시험 결과·조치 판정·재생산 요건은 별도 논의 후 정한다. 세부 조건은 [claim_response 데이터 정책](claim_response/DATA_POLICY.md)을 따른다.

시험·재생산을 허용하는 문장은 PR #7에서 이 문장을 바꿀 때 함께 반영한다.
