# 계약 대체 조건의 네 상태

## 구현과 범위

공통 코드·그래프 스키마를 변경하지 않고 materials에서 계약 조건을 분류한다.

| status | 화면 | 의미 |
| --- | --- | --- |
| approval_required | 구매자 승인 필요 | 승인 조건이 명시됨. 특정 대체품의 승인 완료를 뜻하지 않음 |
| prohibited | 대체 불가 | 대체 금지 조건이 명시됨 |
| conditional | 조건 내 허용 | 원문의 목록·규격 등 허용 조건을 별도로 충족해야 함 |
| unknown | 미확인 | 미기재, 인식하지 못한 문구, 혼합 범위 또는 모순 |

원문 인용을 먼저 기존 위치·값 검증기로 검증한다. 검증된 constraints 문장을 contract_policy.py에서 분류한다. 알려진 전체 문장 규칙을 우선 적용하고, 다른 표현에는 모델이 원문 인용과 함께 반환한 policy_status를 사용한다. 이는 계약 조건에 대한 모델 해석이며 부품 사용 승인이나 의미 정확성의 증명이 아니다. 구매자 사전 승인 조건과 승인 전 기존 구성 유지 문장은 같은 상태로 모이며 서로 다른 원문 문자열이라는 이유만으로 충돌 처리하지 않는다. 수량 등 다른 필드의 충돌 판정은 유지한다.

분류기는 미기재·서로 다른 정책·불확실한 모델 해석을 미확인으로 유지한다. 명확히 납기·문서관리만 다루는 전체 문장은 대체 판단에서 제외하되 excluded_clauses로 근거를 남긴다. 모델 프롬프트는 보완 문장과 예외도 개별 인용하도록 한다. 모델의 의미 오해나 추출 누락을 완전히 검증하는 것은 아니며 실제 부품 적용은 별도 승인·기술 검증 경계를 유지한다.

새 해석은 원문 claims와 네 상태·분류 규칙 버전을 함께 저장한다. 기존 저장 결과는 해시와 원본을 수정하지 않고 constraint_fields라는 읽기 파생 결과로 제공한다. 기존 결과를 확인 저장할 때도 동일 규칙으로 검증한다. 사람이 저장한 보류·수정은 자동으로 덮어쓰지 않는다. API 재호출 없이 기존 근거를 재사용한다.

## 파일

- contract_policy.py: 네 상태, 원문 조건 보존, 보완 조건 결합.
- contract_intake.py: 인용 검증 후 조건 분류. 실제 충돌·잘못된 근거 유지.
- contract_interpretation.py / library_review.py: 추출 지침, 기존 결과 파생 표시, 확인 저장 검증.
- contract_readiness.py / library_static/app.js: 자동 검토와 해석 확인 화면에 상태 표시.
- auto_review_demo.py / example_contracts: 네 가지 계약서와 로컬 웹 준비.
- tests/materials/test_contract_policy.py: 분류·거짓 충돌·근거 오류·실제 충돌·기존 결과 무결성·DB 확인 저장 검증.

이번 변경은 계약 조건의 추출·분류·표시와 검토 저장 범위다. 구매자 승인 기록의 자동 수집이나 뒤의 대체품 적용 승인 로직 변경은 포함하지 않는다. 특히 conditional 상태만으로 대체품 적용 권한을 부여하지 않는다.

## 테스트 계약서

example_contracts의 네 UTF-8 TXT 파일을 업로드할 수 있다. 사용자 작업 폴더의 계약서 디렉터리에도 동일 파일을 제공한다. 본문은 공급계약서 형식이며 테스트 문구를 넣지 않았다. 구매자 이름과 사업자번호는 작성한 예시 값이다. 조건 내 허용 문서는 합의된 목록의 적용 범위를 표현하며, 실제 승인 목록 데이터 자체를 제공하지는 않는다.

웹 목록의 [대체 조건 테스트] 네 건은 동일 문서와 결정적 해석 대역으로 등록했다. 유료 모델 호출은 하지 않았다. 새 파일을 업로드하거나 다시 해석하면 기존 실제 모델 API를 사용한다.

```sh
python3 -m ontologics.materials.auto_review_demo --local-test-fixtures --policy-scenarios --schema a_contract_library
```

## 검증

분류·원문·고객·웹 회귀 70개 통과. 이후 근거 검사 강화와 기존 결과 저장 호환성을 포함한 신규 정책 테스트 9개 통과. 브라우저에서 네 상태와 해석 유지/미확인 기본값을 확인했다. 최종 materials 전체 회귀 486개가 274.922초에 모두 통과했다. JavaScript 문법 및 git diff 공백 검사도 통과했다. 실제 모델 API를 통한 새 추출 정확도는 이번 검증에 포함하지 않았다.

2026-11-02 실제 API 검증과 추가 보완 결과는 [실제 API 검증 기록](2026-11-02-live-contract-verification.md)을 따른다.
