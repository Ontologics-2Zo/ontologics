# 공정 자재 필요량 검토와 RFQ Implementation Plan

목적: 제품별 통합 화면의 공정 자재를 필요량 검토·저장→부족 확인→선택 품목 RFQ 초안 저장/재조회/다운로드로 연결한다. 사용자 요청에 따라 실제 소비 차감 및 실시간 화면 갱신은 제외한다. RFQ 외부 발송·발주·공정 사용 승인도 수행하지 않는다.

1. tests/materials/test_process_rfq.py: 단위/Decimal/미확인 유지, 확인된 총필요량만 계산, 최신 재고 검증, 권한·저장 무결성·재조회 검증.
2. library_process_rfq.py: 기존 공정 근거/공용 재고를 읽고 작업명·생산 수량·담당자 입력 총필요량·근거를 감사 경로로 저장. 검토별 부족품을 선택해 별도 미발송 RFQ 초안을 저장한다. 재고/참고자료/만료 상태를 재확인한다.
3. contract_library_web.py: 엄격한 입력키의 읽기/검토저장/RFQ저장 API 연결.
4. library_static/app.js: 각 제품 공정 표 아래 필요량 입력, 저장한 검토 선택, 부족 결과, 공급사/희망 입고일/납품처/의견, RFQ 저장·다운로드.
5. 격리 DB·관련 회귀 및 로컬 웹 API 검증. 테스트 수량을 실제 회사 실측으로 표현하지 않는다.

담당자 입력은 이번 작업 전체 필요량이며 단위는 자재 기본단위를 따른다. 빈칸은 미확인, 0은 근거가 있는 명시적 미사용이다. 조건부 이론량을 자동 입력하지 않는다. 동일 제품의 여러 작업은 독립 검토 ID로 관리한다. 필요량 검토/RFQ 자체는 재고 예약이 아니다.

완료: 필요량 검토/미발송 RFQ 원장과 API, 제품별 입력·검토 선택·부족품 선택·문서 저장/재조회/다운로드를 구현했다. 소수점6자리까지 단위별 계산하고 미확인과0을 구분한다. 재고·만료·원문 변경 시 RFQ 생성 차단, 입력 변경 시 재검토, 권한·CSRF·무결성·재시도 중복 방지를 검증했다.

검증: 관련38개 회귀 통과(85.471초), 최종 공정 RFQ10개 검사 통과(2.897초, HTTP 추가 포함). JS 문법 및 diff 검사 통과. 브라우저 도구 오류는 세션 초기화로 복구했다. 실제 로컬 웹에서 ‘공정 자재 RFQ 업무 검증 · 100대’ 작업에 플럭스20.5g/세정제800mL를 검증 입력으로 명시하여 저장하고 부족7.5g/100mL를 미발송 RFQ로 저장·다운로드 확인했다. 실제 소비량/공정표준으로 주장하지 않으며 사용자 재고 예약·차감·외부 발송 없음. 다운로드 파일: /Users/anseongsu/Downloads/process-material-rfq-845d7632-58fe-4162-a46a-79a371e6073a.txt. 전체 저장소 검사는 이번 변경에서 재실행하지 않았다.
