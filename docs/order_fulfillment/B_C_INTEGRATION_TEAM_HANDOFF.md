# B C 생산 재고 출하 통합 협의안

작성일: 2026-10-27, Asia/Seoul  
발신 역할: B 생산·재고·납품 수량 담당  
수신 역할: C 개별 보드·생산 및 이동 이력 담당, 공통 모델 담당  
상태: 협의안. 담당 범위와 제안 명칭은 아래 결정표에서 확정한다.

B의 생산 작업·완성품 재고·출하 수량과 C의 개별 보드 이력을 연결하려고 합니다. 같은 개념은 공통 명칭과 ID를 쓰고, 작업별 집계와 보드별 기록은 참조로 연결하는 방식을 제안드립니다. C 구조는 공유된 캡처를 기준으로 정리했으므로 실제 타입·필드와 다른 부분은 회신 부탁드립니다.

## 공통 명칭 제안

| 개념 | 공통 이름과 참조 필드 제안 | 적용 기준 |
| --- | --- | --- |
| 제품 구성 | Configuration / configuration_id | 개정·변형이 같은 구성은 공통 ID 사용 |
| 개별 보드 | ProductUnit / unit_id | 동일 회사·동일 일련번호의 보드를 공통 식별. 회사 간 같은 일련번호는 별개 |
| 생산 작업 | ProductionWork / production_work_id | C의 보드별 생산 기록에서 B 작업을 참조. 스냅샷 간 작업 식별은 별도 합의 |
| 완성품 재고 집계 | FinishedGoodsStock / stock_id | 같은 회사·구성·위치·관측 시점·집계 범위를 표현할 때 사용 |
| 출하 건 | Shipment / shipment_id | 실제 같은 출하 건을 연결할 때 사용. shipment_id는 연결 필드 제안이며 현재 B 타입명은 Shipment |
| 계약상 납품 회차 | DeliveryRound / delivery_round_id | 고객·수량·도착 기한에 대한 약속 단위 |
| 생산라인 | ProductionLine / production_line_id | 공통 조회에 필요하면 정의. 현재 B 모델에는 없음 |

현재 B 모델은 [model.py](../ontologics/model.py)에 정의되어 있습니다. 기존 타입 이름을 재사용하되, 공통 ID 생성·중복 판정·버전 규칙까지 함께 맞추면 병합 후 대응 작업을 줄일 수 있습니다.

## 별도로 유지할 개념

| 구분 | 의미 | 연결 방식 |
| --- | --- | --- |
| ProductionWork와 UnitProductionRecord | 생산 작업과 개별 보드 생산 기록 | C 기록이 보드별 생산 이력이라면 unit_id와 production_work_id로 연결 |
| ProductionObservation과 UnitProductionRecord | 작업별 누적 수량 관측과 개별 보드 기록 | 이름을 합치지 않고, 시점·범위·완전성이 맞을 때 수량 대조 |
| ProductUnit과 FinishedGoodsStock | 보드 한 대와 특정 시점의 재고 수량 집계 | 보드가 어느 재고 관측에 포함되는지 관계 정의 |
| Shipment와 DeliveryRound | 물리적 출하 건과 계약상 납품 약속 | B는 Shipment → Allocation → DeliveryRound로 연결 |

캡처의 delivery_reference는 참조 대상을 확인한 뒤 명칭을 정해야 합니다. 출하 건을 가리키면 shipment_id, 납품 회차를 가리키면 delivery_round_id가 적합합니다. 외부 문서 번호라면 내부 ID와 구분해 보존하고 대응 관계를 둡니다. 현재 B에는 delivery_reference 필드가 없습니다.

## C 쪽에서 공유 부탁드리는 자료

1. 실제 스키마의 타입·필드·필수 여부·참조 대상. UnitProductionRecord, 생산라인, 창고 보관, delivery_reference 관련 부분을 포함해 주세요.
2. 대표 보드 1대의 생산·창고·출하 이력과 각 참조 ID. 해당 이력이 어디까지 완전한지도 알려주세요.
3. 여러 보드를 묶는 기준. 생산 작업, 창고·구성·시점별 재고, 출하 건에 어느 보드가 속하는지 확인 가능한 목록이면 됩니다.
4. 캡처의 207대와 C-S001~120, C-D001~080이 전체 데이터인지 예시인지, 서로 중복될 수 있는 집합인지, 각각 어느 시점의 상태인지 알려주세요.
5. 현재 사용하는 구성 ID, 회사 식별 값, 일련번호 규칙과 작업 ID 생성 방식.

보드 목록이 일부여도 공유할 수 있습니다. 전체 여부를 함께 표시해야 B에서 확정 수량으로 잘못 계산하지 않습니다.

## B 쪽 현재 제약과 수량 대조 방법

- B 생산 관측은 작업별 누계이며 총생산 = 정상 + 불량입니다. 같은 관측 시각의 작업 완료 수량은 정상 누계와 일치해야 합니다.
- FinishedGoodsStock.quantity는 재고 관측 시점의 수량입니다. 현재 지원 형식에서 관련 사건의 완전성 등이 확인되면 실제 출발 수량을 차감해 현황 시점 잔량을 계산합니다. C의 현재 잔량을 관측 수량으로 넣고 출하를 다시 차감하면 이중 차감됩니다.
- 같은 회사·구성·시점·범위이고 목록이 완전할 때만 개별 보드 수와 집계 수량을 대조합니다. 생산 누계 대조에는 누계 시작 범위와 중복·재작업 기준도 필요합니다.
- B의 현재 출하는 재고 배정 전량에 대응하는 한 건만 지원합니다. 생산 작업 직접 출하·부분출하·분할출하는 별도 확장입니다.
- 부분 생산 완료 기록은 저장할 수 있지만 현재 CQ02 현황 합계는 해당 상태를 미지원으로 처리합니다.
- 출하 예정, 실제 출발, 도착 예상, 실제 도착을 구분합니다. 고객 도착 완료는 실제 도착 사실로 판단합니다.
- 모델의 허용 타입·필드는 명시되어 있습니다. 새 연결은 공통 SCHEMA와 검증에 반영해야 합니다.

현재 운영 예제는 synthetic으로 관리하며, 공개 설계·BOM의 real 근거와 구분합니다. 통합 자료도 원본 위치·근거·데이터 버전을 유지하고 기존 검토·승인 경로로 반영합니다.
