# BOM 회사 공용 재고 연결

요청: 공통 코드 변경 없이 동일 회사 품목의 재고를 제품 간 공유하며, 30개 예약/해제를 양쪽 조회에서 검증한다.

실제 데이터 확인 결과 L/L1 ComponentModel ID는 원본별 ID로 모두 다르다. 기존 부품 ID를 수정하거나 제조사 동일성·전기적 대체 승인을 발명하지 않는다. A 전용 pp_inventory_component_links가 회사 재고 품목 연결과 근거·등록자를 보존한다. 명시적 --seed-stock-links가 L/L1 전체 표기 및 패키지 일치 항목 61쌍을 회사 업무 검증용 동일 재고 품목으로 지정했다. NA/NS/Opened 및 불일치는 연결하지 않는다. 제조사 품번 실사를 대체하지 않는다.

LibraryStock은 연결된 원본 ID를 회사 품목 키로 조회하고 같은 기준 가용량을 양쪽 ID에 제공한다. 예약 원장은 원본 부품 ID를 보존하며 reserved_totals가 회사 품목별로 합산한 뒤 양쪽 ID에 같은 차감량을 제공한다. 기존 계약 자기 예약 제외 규칙, 권한·트랜잭션·감사·예약 해제 규칙을 유지한다. 동일 계획에 별칭이 여러 번 등장해도 같은 풀을 중복 예약하지 않도록 계획 내 할당을 누적 차감한다.

같은 부품의 중복 관측을 더하지 않는다. 최신 구성별 자료에서 부품별 최신 관측을 선택하며, 동일 시점의 충돌 또는 다른 회사/창고는 대사를 요구한다. 실제 창고별 예약 원장 확장은 포함하지 않는다. 연결이 없는 자료는 기존 구성별 조회를 유지한다.

검증: 격리 PostgreSQL에서 실제 계약 원본→해석 대역→사람 검토→제품 연결→BOM 계산→대체 미적용→예약 API→해제 API를 수행했다. 100k/R0402 회사 테스트 품목의 L/L1 가용량이 100/100→L 30개 예약→70/70→해제→100/100, 이어 L1 30개 예약→70/70→해제→100/100으로 변화했다. 예약·해제·재고 계산은 대역이 아닌 실제 서비스/DB를 사용했다. 테스트 스키마만 정리하며 사용자 계획에는 시험 예약을 만들지 않았다.

공용 조회 단위검사 3개(중복 비합산/최신 관측/동일 시점 충돌 및 창고 혼합 거부), 양방향 통합 검사1개 통과. 기존 계약 보관함13개를 포함한17개 회귀 통과. 최종 계획 내 중복 차감 변경 후 경쟁 예약 검사 추가 실행. 로컬 실제 DB 읽기에서 61개 매핑의 L/L1 가용량 동일 확인; L1 나머지13종은 재고 미연결. 사용자 DB에 신규 시험 예약 없음. 전체 저장소 검사는 기존 환경 오류 기록을 유지하며 이번 범위에서는 관련 검사만 실행했다.
