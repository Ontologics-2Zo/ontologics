# B 분리 기존 계획의 실행 보완 — 공통에 추가한 B 코드·문서와 B 연결부

작성일: 2026-10-27 / 상태: **계획 작성. 이번에 제품 코드 이동·수정·검사를 실행한 것은 아님.**

## 1. 기존 계획과의 관계

기존 계획에도 공통 파일에서 B 내용을 분리하는 작업이 있었다. 이번 문서는 그 계획을 대체하지 않고, 실행 순서·검사·차단 범위를 구체화한다.

- [기존 분리 계획](../../JunhwaDocs/06_B체인_분리/B_체인_분리계획.md): 공통 Service/model/Provider 분리, 폴더 구조, 문서·설치 정리, 기준 대조를 이미 명시했다(§2~7).
- [Task02 대응표](../../JunhwaDocs/06_B체인_분리/분리_Task02_변경파일_대응표.md): §4.1에 혼합 Python 파일, §4.5에 README/상태/설정, §6에 연결 의존성을 이미 분류했다.
- [Task03](../../JunhwaDocs/06_B체인_분리/분리_Task03_공통확장_계약확인.md): 공개 확장 접점의 부족을 조사했다. R1~R6 전체를 CQ01의 일괄 선행 조건으로 다시 요구하지 않는다.
- [Task04 추가 조사](../../JunhwaDocs/06_B체인_분리/분리_Task04_추가조사_B연결부_가능범위.md): B 파서·로더·lookup 조립의 임시 검사 30개와 실제 DB 미검증을 구분했다. 이 결과는 새 분리 제품의 검사 통과로 재사용하지 않는다.
- [최소 공통 요청서](b-common-extension-requests-20261027.md): 이 계획에서 남는 공통 요구를 별도 문서로 정리한다.

보완의 핵심은 “공통 확장이 준비될 때까지 B 작업 전체 대기”에서 벗어나, **B 소유 코드 추출·연결 수정·결정적 검사부터 진행하고 실제로 막히는 공통 경계를 증거로 남기는 것**이다. 승인된 계약 저장이 막힌 경우에는 그 단계의 완료를 주장하지 않는다.

## 2. 목표·보존 기준

목표는 새 파일의 위치 정리뿐 아니라, 공통에 박힌 B 타입·검증·조회·역할·문서 의존성을 분리하고 공통의 승인·권한·기록 기능을 그대로 호출하는 것이다. CQ01을 먼저 끝까지 검사한 뒤 CQ02~06으로 확대한다.

실행 시 원래 작업 브랜치·미커밋·미추적·과거 문서·실패 기록을 유지한다. 기존 백업은 열지 않는다. 별도 작업 공간에 안전한 소스/테스트/자료만 선별 복사하고, 비밀 설정·DB·백업·개인 실행 원문은 복사하지 않는다. 기존 브랜치를 전환하거나 복원·reset·일괄 삭제하지 않는다. 이번 계획은 fetch/merge/commit/push/PR/실제 LLM을 포함하지 않는다.

## 4. 실제 실행 순서와 단계별 산출물

의존 순서는 E0→E1→E2다. E4의 문서 이관·설치 조사도 E2 이후 독립적으로 진행할 수 있으며 C01 제공을 기다릴 필요가 없다. E3의 실제 승인 연결은 C01 기반과 안전한 DB가 있어야 실행한다. E5는 E3에서 CQ01 전체 연결이 통과한 뒤 시작한다.

### E0. 현재 작업을 보존하고 대조 자료 준비

- 실행 직전 refs/status/파일 SHA를 새로 기록한다. 기존 Task01 백업/개인 실행 원문은 열지 않는다.
- 별도 사본 A는 현재 동작 비교용, 별도 사본 B는 위 origin/main의 분리 후보 기준으로 만든다. 안전한 작업 공간 생성은 허용 범위에서 진행하되 원본 checkout은 그대로 둔다. 새 팀 기반이 생기면 전체 SHA를 기록한 별도 사본으로 비교한다.
- 공통 코드·공통 테스트·설정·원본 파일의 해시 목록과 B 추가 허용 경로를 따로 만든다. 기준 main 사본에 현재 공통 파일을 통째로 덮어쓰지 않는다.
- 산출물: 기준 manifest, 블록 분류표(B/범용/기존 공통/문서·설정), 검사 실행 환경 목록.
- 완료: 원본 기존 파일 누락0·변경0, 원래 Git refs/status의 기존 항목 동일. 작업 공간은 소스 외 비밀·DB 복사0.

### E1. 이동 전 동작을 회귀 검사로 고정

- tests/test_contracts.py와 tests/test_delivery.py의 파서·그래프·도구 검사를 내용별로 골라 기존 정답과 오류 조건을 기록한다. test_delivery는 CQ01이며 이름만 보고 CQ04로 분류하지 않는다.
- model/provider/runtime/service의 기존 공통 검사를 B 추가 검사와 구분한다. 누락된 회귀는 분리할 책임 경계에만 먼저 작성한다. 원본 테스트 파일은 바꾸지 않는다.
- 정답은 data/b_contract_expected.json 및 data/sources/b_demo_contract_01.md와 대조한다. 제품·구성의 추가 근거까지 정확 집합으로 검사하며 구현에 맞춰 독립 정답을 바꾸지 않는다.
- DB/환경파일/네트워크 차단 조건에서 순수 검사를 먼저 실행한다. DB 필요한 기존 테스트는 명시적으로 별도 목록에 둔다.
- 완료: 선택한 각 검사의 입력·기대값·실제 결과·기준 사본이 기록되고 기존 실패가 분리 회귀와 구별됨. 과거 43/30 통과 수치를 이번 결과로 재사용하지 않음.

### E2. CQ01 B 코드와 연결부를 먼저 구현·검사

- ontologics/order_fulfillment/에 CQ01 파서·추가 스키마·검증·lookup 조립·역할 정의를 최소 모듈로 추출한다. 설치 패키지가 examples를 import하지 않게 한다(examples/b_agent.py:16의 역의존 제거 대상).
- B 로더는 실제 source/fixture/catalog 경로를 인자로 받도록 수정한다(현재 contracts.py:176). 논리 SourceDocument.path/ID/SHA/locator는 유지한다. 원본은 기존 data/sources/에 그대로 공급하고 fixture/정답만 data/order_fulfillment/에 배치한다.
- b_intake/b_promise 역할 ID는 유지한다. intake는 기존 prepare_draft/get_draft/validate_draft를, promise는 기존 lookup(version=...)을 사용한다(host.py:165,169). 새로운 B 도구를 lookup 인자에 숨기지 않는다.
- B 순수 함수가 반환 노드의 회차→항목→계약/구성→개정/제품을 연결한다. 결과에 명시 data_version·정확 근거/원본 metadata·실제 lookup run_id들을 남긴다. 별도 delivery_round run_id를 만들지 않는다.
- Provider는 기존 callable protocol을 우선 사용하고 CQ01에 필요 없는 CQ03~06 내부 훅을 선행 요구하지 않는다(runtime.py:64).
- 현재 사본 A에서는 기존 내장 타입을 활용해 B 연결의 호환성을 비교한다. 기준 사본 B에서는 B 순수 코드와 응답 대역 검사를 실행하고 UNKNOWN_TYPE 등 실제 거부를 확인한다. A의 성공을 공통에서 B 정의가 제거된 성공으로 표현하지 않는다.
- 완료: 아래 V01~V06 통과, 공통 사본 해시 변경0. Source/Evidence만 승인한 것을 계약 추출값 승인으로 대체하지 않음.

### E3. 공통 경계를 실제 실패 기준으로 좁히고 CQ01 승인 경로 검사

- [공통 요청서](b-common-extension-requests-20261027.md)의 C01을 필수로 남기고, C02~C04는 선택한 방식에서 실패하는 경우에만 활성화한다. 요청에는 호출 입력·오류·파일/줄·기대 결과·최소 수락 검사를 첨부한다.
- 공통 수정은 이 B 구현에 몰래 포함하지 않는다. 제공된 기반은 별도 SHA/변경 목록으로 기록한다. 기반이 없더라도 E2와 독립 문서 추출 준비는 끝내며 막힌 승인/반영만 미실행으로 남긴다.
- C01 기반이 있으면 B 정의의 같은 구성이 validate_graph/초안/검토/반영/JSON-LD/T-box 전 경로에 적용되는지 먼저 검사한다(service.py:455,484,519,541).
- 안전한 전용 테스트 DB가 확인된 경우에만 source→후보→초안→다른 사람 승인→반영→명시 버전→Host promise의 한 시나리오를 실행한다. tests/db.py의 DATABASE_URL fallback을 그대로 믿고 실행하지 않는다.
- 완료: V07~V10 통과 시 CQ01 전체 분리 연결 성공. 응답 대역만 통과하거나 전용 DB 부재 시 그 수준까지만 기록하고 기존 Task05 진입 조건을 충족했다고 표시하지 않음.

### E4. 공통 문서의 B 본문과 설치·버전 결합 정리

- 별도 사본에서 README/PROJECT_STATUS/docs/SERVICE_SPEC.md/docs/TOOLS.md/docs/AGENT_RUNTIME.md의 B 블록만 추출한다. B 실행 안내는 docs/order_fulfillment.md, 긴 이력은 docs/order_fulfillment_history.md 후보로 나눈다.
- 날짜·당시 커밋·실패·비용·대역/실제 모델 구분을 보존한다. 기존 JunhwaDocs와 원래 checkout 기록은 수정하지 않는다. 이관 전후 모든 B 블록의 목적지/해시 대응표를 만든다. 현재 성공으로 과거 기록을 재작성하지 않는다.
- 원래 main 기반 사본에는 B 문서를 추가하고, 현재 사본에서 추출했어야 하는 블록과 대조한다. 공통 문서 최소 링크/요약은 별도 문서 통합 변경으로 제출 가능한 형태만 준비한다.
- B 버전은 공통 버전과 구분한다. pyproject/__init__의 현재 버전을 무작정 되돌리지 않는다. 공통 설정을 그대로 둔 설치 방안을 먼저 평가하고, 불가능한 요구만 C04로 남긴다.
- 문서 완료: V11 충족으로 독립 완료한다. C01이나 설치 계약을 기다리지 않는다.
- 설치 상태: V12를 별도로 통과/차단/미실행으로 기록한다. 새 계약 타입의 공통 검증은 C01, 선택한 배포 방식은 필요 시 C04에 의존하므로 문서 완료와 묶지 않는다.
- 공통 코드 변경0, 문서 링크/설치 설정 변경은 별도 집계한다. 문서·설정 변경까지 포함해 ‘모든 공통 파일 변경0’이라고 합산 주장하지 않는다.

### E5. CQ01 통과 후 나머지 CQ를 한 기능씩 확대

- CQ02→CQ03→CQ04→CQ05→CQ06 순서로 계산/검증/처리/역할/Provider를 분리한다. 해당 CQ의 고정 입력·독립 정답·근거·실패 검사를 먼저 실행하고 다음으로 넘어간다.
- 기존 함수/역할/자료 ID/namespace는 유지한다. 서비스 처리기를 그대로 복사해 _run/_nodes에 의존하지 않도록 B 공개 연결부로 바꾼다. 독립 도구 이름 보존이 필수인 CQ에는 C02를 적용한다.
- lookup 호출 수/출력 크기/전체 단계 예산을 CQ별로 측정한다. 기존 max_tool_calls는 응답 한 번의 묶음 제한이며 전체 실행 제한과 다르다. parallel 생성 옵션도 실제 병렬 실행 성공으로 표현하지 않는다.
- 설치·공통+B 회귀·원본 대조를 마친 뒤 검토 가능한 변경 집합을 만든다. 외부 배포·Git 작업·실제 모델 호출은 포함하지 않는다.
- 완료: CQ별 정답/오류/버전/근거·실행 기록 검사와 B 미등록/등록 회귀 통과. 코드/문서/설정/기반 변경 목록이 각각 남음.

## 6. 위험·우회 금지·되돌림

| 위험 | 대응 |
| --- | --- |
| 현재 내장 B 덕분의 성공을 완전 분리로 오인 | 사본 A/B를 분리하고 결과마다 기준 SHA·파일 해시·대역/DB 수준 표시 |
| B 검증만 성공하고 실제 승인에서 UNKNOWN_TYPE | C01 전 경로 일관성 검사. 전역 SCHEMA.update·monkey patch·비공개 객체 교체 금지 |
| Service 복사로 공통 승인/권한/감사 우회 | B는 공개 lookup/초안/Host 호출만 사용. 공통 내부 로직 복제 금지 |
| 문서 정리로 과거 실패 소실 | 원래 checkout 보존, 이관 블록별 대응표·해시와 당시 날짜/실패 유지 |
| 여러 노드 lookup이 예산을 넘김 | 필요한 노드만 조회하도록 수정하고 측정. CQ01 임시 전체 snapshot 조회를 제품 기본값으로 바로 채택하지 않음 |
| 설치 경로 변경으로 SourceDocument 불변 조건 파괴 | 실제 파일 경로와 논리 metadata 분리. 기존 원본 path 유지, 외부 resolver는 필요 시 C04 |
| 테스트가 개발/백업 DB에 연결 | 전용 서버·접속 경로 확인 전 DB suite 미실행. 기존/백업 DB 시작·복원 금지, 비밀값 출력 금지 |

단계 실패 시 원래 작업을 복원하지 않는다. 해당 별도 사본의 작은 변경만 수정하고 마지막 통과 단계에서 재검사한다. 임시 사본을 치울 때에도 필요한 실행 코드·manifest·로그를 보존한 뒤 안전하게 정리한다.

## 7. 완료 보고와 다음 실행의 시작점

다음 실행은 E0 보존 대조와 E1 회귀 고정에서 시작한다. 공통 확장 부재만을 이유로 E2를 생략하지 않는다. E3의 실제 승인 경로가 막히면 B 코드/연결부의 실행 결과와 그 한계를 보고하고, 공통 요청서의 해당 항목만 근거와 함께 남긴다.

보고는 ①이번 변경 파일 ②B에서 단순화/재사용한 내용 ③실행한 검사와 실제 결과 ④미실행과 이유 ⑤필수/조건부 공통 요청 ⑥보존 대조 ⑦CQ별 다음 진입 가능 여부를 구분한다. 문서 작성·코드 구현·대역 통과·실제 DB 수직 연결·실제 LLM을 같은 완료 상태로 표현하지 않는다.

계획 작성 턴의 산출물은 이 보완 계획과 별도 공통 요청서다. 원래 B 분리 계획·Task01~04·개인 기록을 대체하지 않는다.
